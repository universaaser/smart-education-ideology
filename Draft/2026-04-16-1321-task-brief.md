# Latest Task Brief

## 结论
本项目当前已经形成可构建的前后端 demo：包含登录与角色分流、教师/学生基础界面、知识图谱展示与 Excel 导入、资源上传解析流程、爬虫入库框架、AI 对话与学习路径推荐等能力。前端 `npm run build` 与后端 `mvn -q -DskipTests package` 均通过。

## 当前项目完成情况

- 后端基础：Spring Boot + MyBatis-Plus + MySQL 配置存在，已定义用户、课程、资源、知识图谱、聊天、解析任务、学习活动等数据表。
- 知识图谱：已有节点/关系查询、位置更新、关系创建、Excel 模板下载与导入接口，前端有图谱页面和导入入口。
- AI 对话：已有聊天会话、消息发送、选段解释、模型选择入口和后端 provider 路由，但 Gemini 仍是预留/回退逻辑。
- 资源与爬虫：已有资源 CRUD、爬虫启动/停止/状态接口，当前规则主要覆盖人民网、中国共产党新闻网/学习类站点，爬取后尝试 AI 归纳思政标签。
- 上传解析：已有文件上传、解析任务状态轮询、AI 分析结果展示和入库流程，但不是正式 MinerU 文档结构化解析。
- 学习路径：已有基于知识关系的推荐接口和学生首页展示，属于初版路径推荐，不等于完整个性化学习系统。
- 学生预警：后端有按学习时长、正确率、专注度、情绪字段计算预警等级的服务，但缺少真实采集链路和完整页面闭环。

- 测试：缺少单元测试、接口测试、爬虫容错测试、上传解析测试和端到端验收脚本。

## 当前 demo 临时妥协点
- 文档解析妥协：`AiIntelligenceService.parseDocument` 不是正式 MinerU API 调用；文本读取失败时会根据文件名推断内容，AI 失败时返回 placeholder。
- AI 配置妥协：`application.yml` 有默认代理 key、DeepSeek/MinerU 占位 key、OpenAI/Gemini 默认关闭；这适合演示，不适合作为生产配置。
- Gemini 妥协：后端 `callGemini` 明确提示未实现并回退到 OpenAI-compatible provider，不能宣传为 Gemini 已真实接入。
- 爬虫妥协：站点规则数量有限，AI 分析失败时使用默认思政标签，可能造成知识库来源真实但分析结果不可信。
- 预警妥协：`AlertService.getAlertStatistics` 当前返回 total 和固定 0 分类，不是真实等级统计；预警输入也没有真实采集闭环。
- 学习推荐妥协：推荐主要依赖图关系和简单优先级，未使用真实学习画像、错题、掌握度和长期行为数据。
- 前端用户妥协：部分 API 默认 `userId = 1` 作为兜底，演示可用，但正式多用户场景可能串数据。
- 数据妥协：数据库脚本包含大量示例数据和旧表迁移逻辑，正式项目需区分 schema、migration、seed/demo data。
- 安全妥协：token 存在 localStorage，上传文件路径、头像上传、爬虫触发、管理员能力等需要更严格的权限与安全校验。
- 可维护性妥协：源码中文字符串和注释出现编码损坏，后续维护者阅读成本高，正式验收前应修复。
- 构建妥协：前端构建通过，但产物 chunk 超过 500KB，当前只是警告；若部署到弱网环境需考虑按路由拆分。
