# Keyword Tasks

## 结论

本次完成 PRD 第 5 包“课程关键词采集任务”的 demo 闭环，5.1-5.6 已达到本文完成边界，5.7 外部资讯 API 仍为可选 `[TODO]`。

## 改动原因

- 对应 `/Draft/毕设.md` 中“输入关键词、自动抓取行业动态并进行价值提炼”的教师侧任务流。
- 现有资源库和 AI 摘要能力已经具备基础，本轮优先用已审核资源完成可演示闭环，避免新接外部资讯 API 扩大风险。

## 具体改动

- 新增 `keyword_tasks`、`keyword_task_items` 迁移脚本，并同步写入 `schema.sql`。
- 新增关键词任务实体、Mapper、DTO、`KeywordTaskService` 和 `KeywordTaskController`，支持创建、列表、详情、同步运行和接受结果。
- 前端新增 `views/KeywordTasks.tsx`，并在 `types.ts`、`Sidebar.tsx`、`TeacherShell.tsx`、`services/api.ts`、`RoleAccessService` 接入菜单、权限和 API。
- 接受结果写入 `resources`；若来源链接已存在，则复用已有资源并更新任务 item，避免唯一索引冲突。

## 方案取舍

- 任务运行采用同步执行，不引入队列或轮询框架，满足 demo 级状态流转。
- 第一版复用 `ResourceService.searchForChatContext` 的 `APPROVED` 资源检索，不直接调用 NewsAPI/GDELT/arXiv。
- 接受结果默认写入已审核资源，用于保证接受后资源库可见；正式审核策略后续可改为进入 `PENDING`。

## 风险与注意事项

- 目标数据库仍需执行 `migration_keyword_tasks.sql` 或使用更新后的 `schema.sql` 初始化。
- 尚未做真实浏览器手动验收。
- 外部资讯 API、异步任务队列、失败重试、接口级权限验证和更完整课程归属策略未做。
- 结果来源当前来自已审核资源检索，不等价于真实联网行业动态抓取。

## 验证情况

- `npm run build`：通过，生成 `KeywordTasks` 懒加载 bundle。
- `mvn -f backend/pom.xml -Dtest=KeywordTaskControllerTest,KeywordTaskServiceTest test`：7 tests，0 failures，BUILD SUCCESS。
- 代码审查后修复两点：前端课程列表改用已有 `dashboardApi.getCourses()`；后端接受重复来源链接时复用已有资源，避免 `resources.uk_source_url` 冲突。

## 下一位 agent 的接手提示

下一步建议进入 PRD 第 6 包“专业知识-思政元素匹配审核”。若继续打磨第 5 包，优先做浏览器手动验收、接口级权限验证、接受结果进入 `PENDING` 的产品取舍，以及真实外部资讯 API 接入。
