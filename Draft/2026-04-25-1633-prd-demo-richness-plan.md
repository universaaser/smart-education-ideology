# PRD Demo Richness Plan

## 结论

当前系统主模块已经较多，展示短板不在“有没有页面”，而在“动态闭环、真实数据感、可视化细节和管理深度”。后续应优先补答辩或演示时一眼能看出来的功能：学生做题数据、教师工作台聚合、章节-知识点-材料闭环、知识源自动更新状态、AI 场景测试、视觉监测演示、班级组织、图谱维护能力和稳定演示数据。

本文档只作为后续执行规划，不代表任何功能已经实现，不修改 `Draft/PRD.md` 状态，也不修改 `Draft/2026-04-16-1337-acceptance-checklist.md` 验收状态。真正实现任一功能包时，再按项目规则同步 PRD、验收清单、变更索引和独立变更文档。

## 优先级总览

- `P0`：最建议优先做，直接提升演示闭环和页面丰富度。
- `P1`：增强完整度和论文可写性，可在 P0 稳定后推进。
- `P2`：有价值但可放后，主要降低演示准备成本。

| 优先级 | 功能包 | 演示价值 | 主要补齐点 |
| --- | --- | --- | --- |
| P0 | 学生测验与答题正确率闭环 | 高 | 真实答题入口、正确率、错题和学习画像 |
| P0 | 教师 Dashboard 聚合工作台 | 高 | 第一屏体现多模块数据和待办 |
| P0 | 章节-知识点-材料关联展示 | 高 | 课程、图谱和材料形成可见闭环 |
| P0 | 知识源定时更新与失败重试面板 | 高 | 知识库自动更新更像完整系统 |
| P1 | AI 场景路由测试与效果预览 | 中高 | 模型配置页从表单变成可验证能力 |

| P1 | 图谱节点编辑与导入历史 | 中 | 图谱更像可维护知识工程工具 |
| P2 | 演示数据包与验收结果填报 | 中 | 降低空数据和演示不可复现风险 |

## 功能包细化

### P0-1 学生测验与答题正确率闭环（已完成，2026-04-25 16:47）

**目标**：补齐 PRD 中 `1.7 答题正确率` 和验收清单里“真实答题入口缺失”的短板，让学习报告、预警和复习建议具备真实答题数据来源。

**用户故事**：学生在课程学习后进入 `Practice / Quiz`，完成少量题目并提交答案；系统记录正确率、错题和关联知识点；学生首页展示答题表现，教师或预警模块可据此识别薄弱点。

**建议页面/入口**：
- 学生端新增 `Practice / Quiz` 页面，或先内嵌在 `StudentHome` 的课程卡片中。
- 教师端可在材料生成结果已有题目基础上增加 `Publish Quiz` 或轻量发布入口。
- 学生学习报告增加答题次数、正确率、薄弱知识点。

**后端能力**：
- 新增测验读取接口，优先复用教学材料中的结构化 assessment questions。
- 新增答题提交接口，保存学生、课程、题目、答案、正确性、知识点、提交时间。
- 学习报告聚合答题次数、正确率和错题知识点。
- 预警服务可把低正确率作为学习建议依据。

**数据记录**：
- 推荐新增 `student_quiz_attempts` 和 `student_quiz_answers`，或用一个简化答题记录表先保存明细。
- 记录必须能追溯到 `studentId`、`courseId`、`questionId` 或题目快照、`knowledgePointId`、`isCorrect`。

**完成边界**：
- 至少支持选择题或简答题中的一种，优先选择题。
- 学生能提交答案并得到正确/错误反馈。
- 后端保存答题记录。
- 学生首页或报告能展示正确率。
- 不要求复杂考试系统、限时考试、主观题自动评分。

**验收方式**：
- 准备一个含选择题的课程材料版本。
- 学生打开测验，提交至少 3 题。
- 刷新学生首页或学习报告后，正确率和答题记录仍可见。
- 后端定向测试覆盖提交答案、统计正确率、空题目或非法答案。

**风险与可放宽项**：
- 若现有材料题目缺少稳定 ID，可先保存题目快照。
- 第一版只做学生侧练习，不做正式考试、排行榜和成绩发布。

**实现记录（2026-04-25 16:47）**：已按最小边界完成。学生首页内嵌 `Practice / Quiz`，读取课程材料中的单选题，提交后返回正确/错误反馈；后端用 `answer_submit` 事件保存学生、课程、材料、题目索引、题目快照、答案、正确性、知识点和提交时间；学习报告展示答题次数、正确数、正确率和薄弱知识点数量；预警服务纳入近 7 日低正确率判断。未做正式考试、限时考试、排行榜和教师发布入口。

### P0-2 教师 Dashboard 聚合工作台（已完成，2026-04-25 17:30）

**目标**：让教师登录后的第一屏展示系统丰富度，而不是只靠侧边栏体现功能多。

**用户故事**：教师进入 Dashboard 后能看到今日待处理事项、最近解析任务、学生状态、资源审核、匹配审核和课程材料发布情况，并能一键跳转处理。

**建议页面/入口**：
- 直接增强现有 `Dashboard`。
- 增加待办卡片、趋势卡片和最近活动列表。
- 每张卡片跳转到 `Alerts`、`Source Management`、`Match Review`、`Resource Upload` 或 `Course Library`。

**后端能力**：
- 新增或扩展 Dashboard 汇总接口，聚合已有模块计数。
- 至少返回待处理预警数、待审核资源数、待审核匹配数、最近解析任务、课程材料统计、学生活跃趋势中的 4 类。

**数据记录**：
- 优先读取现有 `student_alert_records`、资源审核字段、匹配审核字段、`parse_tasks`、`teaching_materials`、`student_activity_events`。
- 不新增表，除非现有数据无法支撑聚合。

**完成边界**：
- Dashboard 至少聚合 4 类已有模块数据。
- 每个卡片可跳转到对应功能页。
- 空数据有合理空态。
- 不要求复杂 BI 图表或实时推送。

**验收方式**：
- 使用现有演示数据打开教师 Dashboard。
- 确认至少 4 个模块的计数或列表可见。
- 点击卡片能到达对应页面。
- 后端测试覆盖空数据和有数据聚合。

**风险与可放宽项**：
- 若跨模块聚合一次性查询复杂，可先由多个轻量接口并行加载。
- 不追求统计强一致，演示场景允许刷新后更新。

**实现记录（2026-04-25 17:30）**：已按最小边界完成。后端新增 `/api/dashboard/overview`，聚合待处理预警、待审核资源、待审核匹配、失败解析任务、最近解析任务、材料发布统计和近 7 日学习事件趋势；前端 Dashboard 增加可跳转待办卡片、材料发布卡片与最近解析任务列表，并将 Open Alerts 跳转修正到 Alerts。未新增数据库结构，未做复杂 BI 图表和实时推送，真实浏览器手动验收仍待执行。

### P0-3 章节-知识点-材料关联展示

**目标**：让课程章节、知识图谱和教学材料形成可见闭环，强化课程知识组织能力。

**用户故事**：教师查看课程章节时能看到关联知识点和材料版本；打开图谱节点时能反向看到所属课程、章节和来源材料；学生也能沿章节进入知识点或材料。

**建议页面/入口**：
- `ResourceLibrary` 的章节分组中展示关联知识点数量和材料版本。
- 章节详情抽屉或面板展示知识点列表。
- `KnowledgeGraph` 节点详情展示所属课程、章节和来源材料。

**后端能力**：
- 新增章节-知识点绑定接口，支持列表、绑定、移除。
- 图谱节点详情接口补充课程、章节、材料来源摘要。
- 资源库课程材料分组接口返回章节关联知识点数量。

**数据记录**：
- 推荐新增 `course_chapter_knowledge_points` 绑定表，避免把章节归属硬写入知识点主表。
- 图谱节点来源可优先从现有材料 trace 和知识点来源表聚合。

**完成边界**：
- 至少支持章节绑定知识点并展示。
- 至少一个页面能从章节跳到知识点或图谱节点。
- 不要求复杂拖拽编排和批量冲突处理。

**验收方式**：
- 教师为一个章节绑定 2 个知识点。
- 资源库章节下能看到知识点数量或列表。
- 从章节跳转到图谱节点或知识点详情可用。
- 后端测试覆盖绑定、重复绑定、移除和查询。

**风险与可放宽项**：
- 若图谱跳转定位复杂，可先打开图谱并选中节点详情。
- 第一版不做章节和知识点自动匹配，只做手动绑定。

### P0-4 知识源定时更新与失败重试面板

**目标**：让“思政知识库自动更新”更像完整系统，而不是只靠手动抓取。

**用户故事**：教师或管理员在 Source Management 中查看知识源调度状态，知道下一次更新时间、最近成功/失败结果，并能对失败任务手动重试。

**建议页面/入口**：
- `Source Management` 增加调度配置区。
- 来源列表增加启用调度、周期、下次运行时间、最近运行状态。
- 运行日志中增加 `Retry Failed` 操作。

**后端能力**：
- 保存每个来源的调度启用状态、周期和下次运行时间。
- 记录定时任务运行日志、成功数、失败数、失败原因。
- 提供失败任务重试接口。
- 明确标记 demo/local scheduler 运行限制。

**数据记录**：
- 可扩展 `crawl_sources` 增加调度字段。
- 复用或扩展 `crawl_run_logs` 记录调度触发、手动触发、重试触发。

**完成边界**：
- 页面能配置或展示调度状态。
- 后端能记录定时任务运行日志。
- 失败任务可重试。
- 不要求分布式调度或高可靠任务队列。

**验收方式**：
- 为一个来源启用调度并保存。
- 手动触发或模拟调度运行后，运行日志可见。
- 对失败日志执行重试，生成新的运行记录。
- 后端测试覆盖调度配置保存、日志记录和重试入口。

**风险与可放宽项**：
- 第一版可用本地 Spring scheduler 或仅保留可配置状态加手动触发，不做跨进程可靠调度。
- 外部站点不可用时必须展示失败原因，不伪造成功。

### P1-1 学生视觉/专注度 Demo Mode

**目标**：增强“学习状态监测与预警”的可见性，补齐摄像头授权、隐私说明和专注度指标的演示空白。

**用户故事**：学生在学习页看到视觉监测演示面板，了解系统可分析专注度、情绪和疲劳；即使没有真实视觉模型，也能通过明确标记的 demo 数据体验预警闭环。

**建议页面/入口**：
- `StudentHome` 或学习报告中新增 `Demo Vision Mode` 面板。
- 展示摄像头授权说明、隐私提示和关闭机制说明。
- 显示 `focus`、`emotion`、`fatigue` 三类指标。

**后端能力**：
- 可先新增 demo 视觉结果上报或生成接口。
- 将 demo 结果纳入预警输入或学习报告时必须带 `demoMode=true`。

**数据记录**：
- 可记录在 `student_activity_events` payload 中，或新增简化 `student_vision_events`。
- 必须区分 demo 数据和真实模型数据。

**完成边界**：
- 用户能看到授权说明和指标面板。
- 拒绝授权不影响主流程。
- demo 数据不能在验收清单标为真实视觉分析完成。

**验收方式**：
- 学生打开面板，看到隐私说明和三类指标。
- 拒绝或关闭授权后页面仍正常。
- 若写入事件流，报告或预警能识别 demo 来源。

**风险与可放宽项**：
- 不接真实摄像头时必须清楚写 `Demo Vision Mode`。
- 不做真实人脸识别、情绪识别和后台上传视频。

### P1-2 AI 场景路由测试与效果预览

**目标**：让模型配置页不只是配置表单，而能展示不同 AI 场景的运行差异和可用性。

**用户故事**：管理员在 Model Settings 中选择 Chat、Document Parsing、Question Generation 等场景，点击测试后看到当前 provider/model/base URL、耗时和成功/失败结果。

**建议页面/入口**：
- 在 `Model Settings` 增加 `Scenario Test` 区块。
- 场景选项包括 Chat、Document Parsing、Question Generation、Vision、Embedding。
- 测试结果展示 provider、model、base URL、latency、status、message。

**后端能力**：
- 扩展现有 provider 测试接口或新增场景测试接口。
- 按场景读取当前路由配置。
- 返回安全脱敏结果，不泄露 API key。

**数据记录**：
- 第一版可不持久化测试记录。
- 如需展示历史，可记录最近 10 次测试结果，但不作为完成边界。

**完成边界**：
- 至少 3 个场景可测试。
- 测试结果可见且不会泄露 API key。
- 不要求所有 provider 真正可用。

**验收方式**：
- 管理员选择 3 个不同场景并点击测试。
- 成功或失败都有明确反馈。
- 响应中不包含完整密钥。
- 后端测试覆盖场景路由读取和失败返回。

**风险与可放宽项**：
- 当前可保留固定本地 OpenAI-compatible 默认运行时。
- provider 不可用时展示失败原因即可，不把失败吞掉。

### P1-3 管理员班级/组织最小闭环

**目标**：让管理员侧从“用户和课程绑定”升级为更完整的教学管理，但不扩大成复杂组织架构系统。

**用户故事**：管理员创建班级，把学生加入班级，再把课程绑定到班级；学生登录后能看到班级对应课程资源。

**建议页面/入口**：
- `Admin Console` 新增 `Classes` tab。
- 班级详情展示学生列表和绑定课程。
- 课程绑定可在班级详情中完成。

**后端能力**：
- 班级列表、新增、编辑。
- 班级添加/移除学生。
- 班级绑定/解绑课程。
- 学生课程读取时合并个人绑定和班级绑定。

**数据记录**：
- 推荐新增 `classes`、`class_students`、`class_courses`。
- 保留现有 `course_students`，不要破坏个人绑定能力。

**完成边界**：
- 管理员能创建班级并添加学生。
- 课程可绑定一个班级。
- 学生端课程可由班级关系间接可见。
- 不要求学院/组织树、审批流、批量导入。

**验收方式**：
- 创建班级，加入一个学生，绑定一门课程。
- 该学生登录后能看到课程资源。
- 移除学生或解绑课程后，学生端课程可见性变化。
- 后端测试覆盖班级绑定和学生课程合并读取。

**风险与可放宽项**：
- 第一版只做班级，不做学院、专业、年级组织树。
- 若权限尚未全局拦截，文档需标明接口级权限仍待补。

### P1-4 图谱节点编辑与导入历史

**目标**：让知识图谱更像可维护工具，而不只是展示和关系编辑。

**用户故事**：教师能编辑图谱节点描述、标签或难度，查看 Excel 或自动入图的导入历史，并回看某次导入带来的节点和关系。

**建议页面/入口**：
- `KnowledgeGraph` 节点详情增加编辑入口。
- 增加 `Import History` 抽屉或 tab。
- 每条导入记录显示成功数、失败数、来源、时间和错误摘要。

**后端能力**：
- 节点基础字段更新接口。
- 导入批次记录查询接口。
- 导入批次详情可回看节点/关系摘要。

**数据记录**：
- 可扩展现有导入流程，新增 `knowledge_import_batches` 和 `knowledge_import_items`。
- 自动入图也应记录来源类型，如 `RESOURCE_INGESTION` 或 `EXCEL_IMPORT`。

**完成边界**：
- 至少支持节点描述/标签编辑。
- 至少展示导入历史列表。
- 不要求任意历史回滚和多人冲突解决。

**验收方式**：
- 编辑一个节点描述或标签，刷新后仍保留。
- 执行一次 Excel 导入或自动入图后，导入历史可见。
- 导入历史能看到成功/失败数量。
- 后端测试覆盖节点编辑和导入历史查询。

**风险与可放宽项**：
- 第一版导入历史只做记录和回看，不做回滚。
- 自动入图历史若短期难补，可先覆盖 Excel 导入。
