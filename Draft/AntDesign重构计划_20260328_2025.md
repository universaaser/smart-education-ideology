# Ant Design 重构计划

## 结论

这个项目适合使用 Ant Design 重构，但建议采用“渐进式重构”，不建议一次性整体重写。

原因如下：

1. 当前前端页面以后台管理场景为主，包含登录、侧边栏导航、仪表盘、课程库、资源上传、弹窗、列表、表格、表单、状态提示等典型中后台元素，和 Ant Design 的组件能力高度匹配。
2. 当前项目主要使用 React + TypeScript 手写界面，缺少统一的组件体系、交互规范和状态反馈规范，后续继续扩展会增加维护成本。
3. Ant Design 可以明显降低通用页面的开发成本，提高表单、表格、抽屉、模态框、消息提示、布局系统的一致性。
4. 项目中“知识图谱”这类强交互可视化页面具有明显的定制属性，不适合完全交给 Ant Design 组件替代，更适合保留现有自定义实现，只对外围操作区和详情面板进行 Ant Design 化。

## 是否适合重构的判断

适合重构的部分：

- 登录页与注册页
- 教师端与学生端整体布局
- 顶部栏、侧边栏、面包屑、页头
- 仪表盘卡片、统计区、活动列表
- 课程库列表、筛选区、详情弹窗、新建课程弹窗
- 资源上传、资源管理、消息提示、加载态、空状态
- AI 助手的会话列表、输入区、参数配置区

不建议优先替换的部分：

- 知识图谱核心 SVG 画布
- 节点拖拽、缩放、平移、连线绘制等自定义交互逻辑

建议的处理方式：

- 保留知识图谱核心画布逻辑
- 将图谱页面外围的搜索栏、操作栏、抽屉、表单、提示条改为 Ant Design 组件

## 重构边界

本次重构建议遵循以下边界，避免影响现有毕设功能推进：

1. 不改后端接口协议。
2. 不先改业务流程，只替换界面层和通用交互层。
3. 不先动知识图谱底层数据结构与拖拽逻辑。
4. 优先建立统一的 UI 基础设施，再逐页迁移。
5. 保持现有页面路由、视图切换和 `services/api.ts` 调用方式不变。

## 分阶段计划表

| 阶段 | 目标 | 主要工作 | 涉及范围 | 预期产出 |
| --- | --- | --- | --- | --- |
| 第 1 阶段 | 建立 Ant Design 基础设施 | 安装 `antd`、`@ant-design/icons`，接入全局样式与 `ConfigProvider`，统一主题色、圆角、间距、字体层级，封装全局 `App` 容器 | `package.json`、入口文件、全局样式 | 可稳定运行的 Ant Design 基座 |
| 第 2 阶段 | 重构整体框架布局 | 使用 `Layout`、`Menu`、`Avatar`、`Dropdown`、`Breadcrumb`、`Spin`、`Result` 重构教师端和学生端外壳 | `layouts`、`components/Header.tsx`、`components/Sidebar.tsx` | 统一布局、导航和加载反馈 |
| 第 3 阶段 | 重构认证页面 | 用 `Form`、`Input`、`Button`、`Segmented`、`Alert`、`Card` 重构登录注册页，统一校验和错误提示 | `views/Auth.tsx` | 更稳定的登录注册交互 |
| 第 4 阶段 | 重构仪表盘页面 | 用 `Card`、`Statistic`、`Table`、`List`、`Progress`、`Tag`、`Empty` 重构统计卡片、活动区和课程列表 | `views/Dashboard.tsx` | 仪表盘视觉和交互统一 |
| 第 5 阶段 | 重构课程库与资源管理 | 用 `Table`、`Collapse`、`Drawer`、`Modal`、`Form`、`Upload`、`Tabs` 重构课程库、资源上传和资源列表 | `views/ResourceLibrary.tsx`、`views/ResourceUpload.tsx` | 资源管理链路更标准化 |
| 第 6 阶段 | 局部重构知识图谱外围 UI | 保留 SVG 画布，外围改用 `Input`、`Button`、`Tooltip`、`Drawer`、`Select`、`Tag`、`message` | `views/KnowledgeGraph.tsx` | 在不破坏核心交互的前提下提升可用性 |
| 第 7 阶段 | 重构 AI 助手与学生首页 | 用 `List`、`Card`、`Flex`、`Space`、`Empty`、`Skeleton`、`FloatButton` 优化会话区、问答区和学习推荐区 | `views/AIAssistant.tsx`、`views/StudentHome.tsx` | 学生侧和 AI 侧体验统一 |
| 第 8 阶段 | 收尾与规范固化 | 统一消息提示、空状态、异常状态、加载态，清理重复样式，沉淀页面模板和基础组件 | 全局 | 可持续迭代的 UI 规范 |

## 推荐实施顺序

建议按下面顺序推进：

1. 先搭 UI 基座，再改页面。
2. 先改布局和认证页，再改仪表盘、课程库、资源管理。
3. 最后处理知识图谱外围与 AI 助手。

这样做的原因：

- 风险最小，不容易影响现有业务逻辑。
- 能尽快获得统一风格的“整体观感提升”。
- 避免在知识图谱这种复杂页面上过早消耗大量时间。

## 风险与注意事项

1. 当前项目使用较多 Tailwind 类名，而且 `index.html` 中通过 CDN 注入 Tailwind。若直接全面替换，短期内会出现两套样式体系并存。
2. 部分页面存在动态类名拼接，重构时应优先改为 Ant Design 的 `theme token`、`Tag`、`Badge`、`Progress` 等组件表达，减少样式分散。
3. 知识图谱页面的核心问题不在组件库，而在可视化交互本身，因此不应把重构重点放在图谱画布替换上。
4. 如果后续还要继续实现毕设功能，建议把“界面重构”与“功能补全”并行推进，避免 UI 重构阻塞功能开发。

## 最终建议

建议采用以下策略：

- 结论：适合使用 Ant Design 重构。
- 方式：渐进式重构，不推倒重写。
- 优先级：先重构通用后台页面，再局部优化知识图谱外围。
- 原则：保留现有 API 层与核心业务逻辑，只替换 UI 层和交互容器层。

## 下一步建议

如果确认按这个方向推进，下一步最合适的工作是：

1. 先安装并接入 Ant Design 基础设施。
2. 先把 `TeacherShell`、`StudentShell`、`Header`、`Sidebar` 重构成统一布局。
3. 然后从 `Auth` 和 `Dashboard` 两个页面开始迁移，最快看到效果，也最容易验证方向是否正确。
